03 — Checklist kiến trúc

Mười câu hỏi. Mười câu trả lời.

Nhóm câu hỏi theo bốn điểm kiểm tra: boundary, extension, scale/reliability và provenance.

01—05 · Boundary & extension06—10 · Provider, scale & traceability
# Câu hỏi Trả lời ngắn
01 Architectural drivers? Sửa đổi, thay thế, mở rộng, tin cậy, quan sát và tái lập.
02 C4 Context / Container? Context = boundary. Container = Frontend, Backend, Worker, PostgreSQL và module.
03 Domain boundaries? Market = data; Strategy = signal; Experiment = snapshot/job; News = raw item/sentiment.
04 Thêm Strategy ở đâu? Implement `Strategy` + đăng ký `StrategyRegistry` + test.
05 Đổi Search algorithm ở đâu? Implement/register `StrategyGenerator`; downstream nhận `CandidateStrategy` opaque.
# Câu hỏi Trả lời ngắn
06 Provider mới có đổi Frontend? Không. Thêm Adapter/Provider ở Backend; Frontend dùng contract chuẩn hóa.
07 100.000 backtest scale? PostgreSQL queue + `SKIP LOCKED` + lease + 1/2/4 worker benchmark.
08 Service lỗi có lan không? Không. `RECONNECTING`/`STALE`, provider-local failure và Worker retry.
09 Duplicate / retry / order? At-least-once, không global order, idempotent consumer, fencing và dead-letter.
10 Leaderboard truy provenance? Entry → Experiment → Version + Snapshot + seed + execution + build.

Chi tiết implementation và bằng chứng được ghi trong parent Issue #82 cùng các child issue #83–#91.

Checklist · question → observable guarantee03 / 04
Ba câu đầu xác định boundary. Câu bốn đến câu sáu chứng minh hệ thống dễ sửa và dễ thay thế. Câu bảy đến câu chín nói về khả năng mở rộng và độ tin cậy. Câu mười chứng minh leaderboard result có thể tái lập và truy ngược.

04 — Đánh giá kiến trúc

Thiết kế tốt khi có thể kiểm chứng.

Mỗi tiêu chí có một câu hỏi kiểm chứng và một bằng chứng quan sát được trong code, test, dashboard hoặc benchmark.

Tiêu chí Câu hỏi kiểm chứng Bằng chứng / kết quả
Modifiability Thêm MACD sửa bao nhiêu component? Một Strategy implementation + registry + test. Backtester, Evaluator, Ranking, Visualization và Frontend không đổi.
Replaceability Random → Domain-guided ảnh hưởng Backtester? Không. Chỉ `StrategyGenerator` thay đổi; Backtester nhận `CandidateStrategy`.
Scalability Tăng worker count có sửa core code? Không. `SKIP LOCKED`, lease và unique worker identity cho phép tăng replica.
Reliability News hoặc Binance lỗi thì sao? Provider-local failure; Market `RECONNECTING`/`STALE`; Backtest Job retry có giới hạn.
Observability Admin có thấy system health? `/admin/operations` có queue depth, P50/P95, throughput, retry, failure, lease loss, worker và outbox.
Reproducibility Top-K truy exact input? Leaderboard Entry → Experiment → parameters, dataset fingerprint, seed, versions và build revision.
Documentation Context / Container / Dynamic View / ADR khớp code? Tên, hướng dependency, ownership, failure semantics và Mermaid diagrams đồng nhất.
Trade-off Mỗi technology choice có cost? PostgreSQL hiện tại; Redis/BullMQ trì hoãn; mỗi lựa chọn có benefit, consequence và trigger đo được.
PostgreSQLQueue-wait P95 > 1 giây hoặc 2→4 worker < 1.5× khi connection bão hòa.
RedisChỉ thêm khi repeated reads > 50% và API P95 vẫn > 200 ms.
BullMQChỉ xem xét khi PostgreSQL tuning không đủ hoặc cần priority/delay/rate limit phức tạp.
